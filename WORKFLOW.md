# Правка сайта на Тильде (экономно по токенам)

Сайт подключён к репозиторию `katrinstrizh/tilda-site` (публичный, GitHub Pages:
`https://katrinstrizh.github.io/tilda-site/`). В HEAD всего сайта стоит одна строка:
`<script src="https://katrinstrizh.github.io/tilda-site/loader.js"></script>`.
Официальный API Тильды только читает; запись возможна лишь через репозиторий или редактор в браузере.

## Выбор способа (сверху вниз, первый подходящий)

1. **Репозиторий (по умолчанию, дешевле всего).** Стили, скрипты, анимации, виджеты, счётчики,
   скрытие/перестановка блоков, вставка HTML через JS, замена текстов через JS.
2. **Чтение опубликованной страницы через curl** — чтобы узнать селекторы и структуру.
   Без ключей. Никогда не выводить весь HTML: только `rg`/`grep -o` по нужному фрагменту.
3. **Tilda API** (если ключи сохранены как custom-credential `api.tildacdn.info`) — список
   страниц, их id и HTML. Лимит 150 запросов/час. MCP-серверы не нужны: curl делает то же дешевле.
4. **Браузер в редакторе Тильды — последний вариант.** Только то, что невозможно через JS:
   SEO-поля, настройки страниц, новые страницы/блоки, формы и приём заявок, оплата, публикация.
   Собрать все правки в одну сессию, работать по тексту/DOM, скриншот — только для финальной проверки.
   Перед «Опубликовать» спрашивать подтверждение пользователя.

## Порядок работы через репозиторий

1. `gh repo clone katrinstrizh/tilda-site` (или `git pull`, если уже есть).
2. Найти селектор: `curl -s <URL страницы> | grep -o 'id="rec[0-9]*"[^>]*' | head` или поиск
   по тексту рядом с нужным местом. Блоки Тильды — `#rec<ID>`, элементы Zero Block —
   `.tn-elem[data-elem-id="<ID>"]`. Привязываться к `#rec<ID>`, а не к классам `t-`.
3. Правка: общее — `css/common.css`, `js/common.js`; одна страница — `pages/<имя>.css|js` и
   запись в `PAGES` в `loader.js` (`'/путь': { name, css, js }`). Менять точечно через edit,
   не переписывать файлы целиком и не перечитывать неизменённые.
4. JS ждёт DOM (`ready()` в common.js); для Zero Block и динамических блоков — MutationObserver
   или повтор через `setTimeout`, т.к. Тильда дорисовывает их после загрузки.
5. Увеличить `V` в `loader.js`, коммит с трейлером `Co-authored-by: Perplexity <noreply@perplexity.ai>`, push.
6. Проверка: `curl -s https://katrinstrizh.github.io/tilda-site/<файл> | grep <изменённая строка>`
   (Pages обновляется 1–10 мин). Визуальная проверка в браузере — только если правка визуальная
   и пользователь просит, одним скриншотом.
7. Ответ пользователю: что изменено, на каких страницах, как откатить (`git revert`).

## Ограничения

- Новые страницы, блоки, SEO и формы через репозиторий не создаются — только редактор.
- Новая страница в `PAGES` не требует переопубликации в Тильде; изменение строки в HEAD — требует
  «Опубликовать все страницы».
- Секреты (ключи API, пароли) не коммитить: репозиторий публичный.
